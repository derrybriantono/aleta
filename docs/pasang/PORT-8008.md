# ALETA di port 8008 - langkah pasang

Tujuan: ALETA mendapat port sendiri (`http://192.168.10.10:8008/aleta`) supaya
peramban memberinya 6 sambungan sendiri, tidak antre di belakang SIPP/ABT di
port 80. Port 80 tetap melayani `/aleta` seperti sekarang.

Berkas: `deploy/apache/aleta-8008.conf` (cabang `fitur/performa-muat`).

## 1. Pasang (sesi utama, di server)

```bash
# salin berkas dari repo ke Apache
sudo cp deploy/apache/aleta-8008.conf /etc/httpd/conf.d/aleta-8008.conf

# periksa susunan - harus "Syntax OK"
sudo apachectl configtest

# muat ulang tanpa memutus sambungan yang sedang berjalan
sudo systemctl reload httpd
```

SELinux di server `Disabled`, jadi port 8008 tidak perlu diberi label.

## 2. Firewall - DIJALANKAN PENGGUNA SENDIRI

```bash
sudo firewall-cmd --permanent --add-port=8008/tcp && sudo firewall-cmd --reload
sudo firewall-cmd --list-ports      # harus memuat 8008/tcp
```

Sebelum firewall dibuka, 8008 hanya terjangkau dari server itu sendiri.
Ekstensi tetap jalan: ia menguji 8008 dan memakai port 80 bila 8008 tidak
terjangkau (lihat bagian 5).

## 3. Uji

Dari server:

```bash
curl -sI http://127.0.0.1:8008/aleta/            # 307/200 dari portal (bukan 404/503)
curl -s  http://127.0.0.1:8008/aleta/api/install # JSON kecil
curl -sI http://127.0.0.1:8008/                  # 302 ke /aleta/
curl -sI http://127.0.0.1:8008/aleta/uploads/    # dilayani Apache (403/404), BUKAN dari portal
```

Dari komputer petugas (sesudah firewall dibuka):

```bash
curl -sI http://192.168.10.10:8008/aleta/
```

lalu di Chrome buka `http://192.168.10.10:8008/aleta/` - harus langsung masuk
tanpa login ulang bila sudah masuk di port 80 (kuki tidak membedakan port).

Alamat absolut ikut port: `http://192.168.10.10:8008/aleta/api/aleta-ecourt/ekstensi/updates.xml`
harus berisi `codebase="http://192.168.10.10:8008/aleta/...`. Bila masih tanpa
`:8008`, header `X-Forwarded-Host` dari konteks server utama menang - pindahkan
baris `RequestHeader set X-Forwarded-Host "192.168.10.10"` di `aleta.conf` ke
dalam `<If "%{SERVER_PORT} == '80'">`.

Log port ini memuat lama layanan (`%D`, mikrodetik):
`/etc/httpd/logs/aleta8008_access_log`.

## 4. Dampak

| Bagian | Dampak |
| :--- | :--- |
| Kuki sesi Better Auth | host-only, tanpa atribut port - berlaku di 80 dan 8008 |
| Origin tepercaya | portal menambah `http://192.168.10.10:8008` otomatis (env `ALETA_PORT_PORTAL_TAMBAHAN`, bawaan `8008`; kosongkan untuk mematikan) |
| `BETTER_AUTH_URL` | tidak diubah (`http://192.168.10.10/aleta`) |
| Ekstensi - halaman portal | skrip konten berjalan juga di :8008 (pola tanpa port berlaku untuk semua port); izin host `http://192.168.10.10:8008/*` ditambahkan |
| Ekstensi - popup & pekerja latar | memakai `http://192.168.10.10:8008/aleta` bila terjangkau, cadangan port 80; diingat 5 menit (hidup) / 2 menit (mati) di `chrome.storage.session` |
| Ekstensi - widget di halaman SIPP/ABT | secara bawaan tetap `/aleta/api/...` di port 80. Sejak rantai F2 (25 Okt) bacaan GET/HEAD berpindah ke 8008 bila bagian 7 dipasang; lihat di bawah |
| Pembaruan ekstensi (`update_url`) | tetap port 80 |
| Layar publik antrian / ruang sidang | tetap jalan di keduanya |

## 5. Pengalihan otomatis dari port 80 (OPSI, belum aktif)

Ada di bagian bawah `aleta-8008.conf`, dikomentari. Hanya halaman portal
yang dialihkan; `/aleta/api/`, `/aleta/_next/`, `/aleta/uploads/` tidak. Wajib
dibungkus `<If "%{SERVER_PORT} == '80'">` - tanpa itu port 8008 mengalihkan ke
dirinya sendiri. Aktifkan hanya sesudah firewall 8008 terbuka dan diuji dari
komputer petugas.

## 7. Widget SIPP/ABT lewat 8008 (K7, 25 Okt 2026; MATI sampai env diisi)

Skrip konten di halaman SIPP/ABT (`ekstensi-sipp/portal-jalur.js`) memindahkan **hanya bacaan** (GET/HEAD)
ke `/aleta/api/...` ke port 8008, supaya polling widget tidak antre di belakang SIPP/ABT di port 80.
Tulisan tetap di port 80. Ini permintaan lintas asal, jadi portal harus mengizinkan asal halaman SIPP/ABT.

1. Pasang bagian 1-3 di atas (Apache 8008, firewall, uji dari komputer petugas).
2. Di env portal (kontainer `portal`), isi:

   ```
   ALETA_CORS_ASAL_WIDGET=http://192.168.10.10
   ```

   lalu mulai ulang kontainer portal. Tanpa variabel ini portal tidak menambah kepala CORS apa pun
   (perilaku lama) dan widget tetap di port 80. Kepala hanya ditambahkan untuk permintaan yang MASUK
   lewat port tambahan (`ALETA_PORT_PORTAL_TAMBAHAN`), jalur `/api/`, dan asal yang terdaftar persis.
3. Uji dari komputer petugas (Chrome, halaman SIPP terbuka, DevTools > Network): permintaan
   `sipp-konteks` ke `192.168.10.10:8008` dengan status 200; `Access-Control-Allow-Origin: http://192.168.10.10`.
4. Rilis ekstensi (skill `rilis-ekstensi`) membawa `portal-jalur.js` ke Chrome petugas.

Bila 8008 mati/ditutup, ekstensi menguji ulang sendiri tiap 2 menit dan memakai port 80 selama itu;
permintaan yang gagal di 8008 diulang di port 80. Mundur: kosongkan `ALETA_CORS_ASAL_WIDGET` dan mulai ulang portal.

## 6. Mundur

```bash
sudo rm /etc/httpd/conf.d/aleta-8008.conf
sudo apachectl configtest && sudo systemctl reload httpd
sudo firewall-cmd --permanent --remove-port=8008/tcp && sudo firewall-cmd --reload   # oleh pengguna
```

Portal dan ekstensi tidak perlu dikembalikan: ekstensi otomatis kembali ke
port 80 dalam ≤2 menit, dan origin 8008 yang tidak dipakai tidak berbahaya.
